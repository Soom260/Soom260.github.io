# Soom260.github.io — 최수미 개인 홈페이지

## 1. 목적

취업 목적으로 프로젝트 팀원들, 혹은 면접관분들 등께 자신을 소개하기 위한 개인 포트폴리오 홈페이지입니다.
자기소개, 관심 분야, 진행 중인 프로젝트(kreceipt)의 문제의식·접근·현재 상태,
그리고 연락처(이메일·GitHub)를 한 번에 확인할 수 있도록 만들었습니다.
이후에도 계속 업데이트할 예정입니다.

## 2. 주소

- 공개 홈페이지: https://soom260.github.io/
- GitHub 저장소: https://github.com/Soom260/Soom260.github.io

## 3. 실행·수정 방법

사이트의 글, 스타일, 스크립트는 `index.html`에 들어 있습니다. 

다만 프로젝트 섹션 아래의 '작업 링크' 카드는 5주차의 내용을 반영하여 구글 시트에서 읽어 오도록 하였고, 푸터의 '마지막 업데이트' 날짜는 배포한 날(한국 시간)로 들어가게 했습니다. 둘 다 GitHub Actions가(3주차 내용) 매일 한 번, 한국 시간 00:30 무렵에 배포합니다. 

예약 실행 때문에 날짜는 내용을 고치지 않은 날에도 바뀝니다.(아래쪽에 설명되어 있습니다.) '마지막 업데이트'로 그 날짜 기준의 소개와 프로젝트 현황을 확인할 수 있습니다.


### 글을 고치고 올리기

`index.html`을 수정하고 업로드하면 됩니다. 영어 변환은 자동 번역이 아니라, 영어 문구가 각 태그의 `data-en` 속성에 따로 들어 있습니다. 오른쪽 위 `EN`/`KO` 버튼이 이 둘을 바꿔 보여 주는 방식이라, 한국어 문장을 고치면 `data-en`도 고쳐야 합니다.

push하면 Actions의 `Build and deploy site`가 돌고, 1~2분쯤 뒤 https://soom260.github.io/ 에 반영됩니다. 

### 작업 링크를 시트로 관리하기

개인 프로젝트는 업데이트가 용이하도록 구글 시트와 연동해 두었습니다. 시트를 CSV로 웹에 게시하고, 그 주소를 저장소 변수 `SHEET_CSV_URL`에(Settings → Secrets and variables → Actions → Variables)에 저장하여 사용합니다.

시트 첫 줄의 열 이름의 구성은 아래와 동일합니다.

| 열 이름 | 규칙 |
|---|---|
| 제목 | 필수 |
| 내용 | 필수 |
| 분류 | 비우면 '기타' |
| 링크 | `http://` 또는 `https://`로 시작 |
| 공개 | 필수. `Y`인 행만 화면에 나오고 `N`은 숨김 |
| 제목_EN | 선택 |
| 내용_EN | 선택 |
| 분류_EN | 선택 |

`_EN` 세 열은 영어 화면용이라 필수적이지 않습니다. 비워 두면 영어 화면에서도 한국어가 그대로 보입니다. 


시트 내용을 반영하고 사이트의 업데이트 날짜를 표시하는 워크플로가 매일 한국 시간 00:30분에 설계되어 있어, 시트를 고친 내용은 다음 날 반영됩니다. 몇 분 ~ 수십 분 정도 밀릴 수 있습니다. Actions 탭 → `Build and deploy site` → `Run workflow`를 눌러 수동 실행 또한 가능합니다.

그리고 공개 저장소에 60일 동안 커밋이 없으면 GitHub이 예약 실행을 멈추고 메일을 보냅니다.

열 이름이 다르거나, 공개=`Y`인 행이 하나도 없거나, 링크 형식이 틀린 경우 등 시트에 문제가 있으면 배포 자체가 멈춥니다. 이때는 Actions 로그에 멈춘 이유가 나오고, 사이트는 갱신되지 않도록 하였습니다. 링크 형식 오류나 필수 값 누락처럼 특정 행의 문제라면 몇 번째 행인지까지 함께 나오고, 열 이름이 다른 경우에는 현재 시트의 열 이름 목록이, 공개=`Y` 행이 없는 경우에는 그 사실이 출력됩니다.

## 4. 현재 상태

**완성도**
- 자기소개·관심 분야(경영·서비스기획, 사회분석)·프로젝트 소개·연락처(이메일, GitHub) 섹션을 기재하였습니다. 상단 메뉴를 클릭하여 각 섹션 이동이 가능합니다.
- 소개하는 프로젝트 **kreceipt**는 아직 출시 전 컨셉 단계이므로, 화면에 "컨셉·아이디어
  단계 — 사용자 시나리오와 핵심 화면 정리 중"임을 기재하여 미완성 단계임을 명시하였습니다.
- 연락처는 이메일과 깃허브만 공개했습니다.
- 페이지의 유일한 그래픽 요소인 영수증 카드에 `role="img"`와 대체텍스트(alt)를 넣어
  화면에 보이는 내용을 글로도 확인할 수 있게 했습니다.
- 한/영 전환(EN/KO) 버튼 옆에 **음성 안내(🔊)** 토글을 삽입했습니다. 켜면 각 섹션이
  스크롤로 화면에 들어올 때 그 섹션의 대체텍스트를 읽어주며, 언어 전환 상태에 맞춰
  한국어/영어 음성으로 전환됩니다.
- **5주차에 배운 내용을 응용하여, 구글 시트를 수정하여 개인 프로젝트를 업데이트 할 수 있는
  작업 링크 파트를 제작했습니다.** 03 프로젝트 섹션의 kreceipt 설명 아래에
  '작업 링크' 블록이 위치해 있으며, 기재된 프로젝트들은 `index.html`을 고치지 않고 구글 시트에 적어서
  관리합니다. 시트 열은 **제목 / 내용 / 분류 / 링크 / 공개** 다섯 개와
  **제목_EN / 내용_EN / 분류_EN** 세 개를 더해 총 여덟 개이며, 제목·내용·공개는 필수,
  분류를 비우면 '기타'로 들어가고, 링크는 `http://` 또는 `https://`로 시작해야 하며,
  **공개 열이 `Y`인 행만** 화면에 나옵니다. `_EN`이 붙은 세 개는 사이트의 영어 화면을 위한 열이며,
  기재하지 않을 시 언어 설정을 변경해도 한국어 제목 / 내용 / 분류가 그대로 유지됩니다.
- **매일 한국 시간 00:30 무렵 워크플로가 자동 실행됩니다.** 시트를 고쳐 두면 다음날 사이트부터
  반영되고, 바로 반영하고 싶을 때만 Actions 탭에서 `Run workflow`를 누릅니다. push할 때도 돌아갑니다.
- 시트 내용이 잘못된 경우(열 이름이 다름, 공개=`Y` 행이 없음, 링크 형식 오류, 게시된 CSV 주소가
  아닌 경우)에는 배포가 진행되지 않습니다.
- 푸터의 '마지막 업데이트' 날짜를 손으로 고치지 않고, **빌드하는 날의 한국 시간 날짜**가
  자동으로 들어가게 했습니다(예: `2026.10.04`). 위의 워크플로 내에 같이 들어있어
  매일 빌드가 돌므로 '해당 날짜 기준의 현황'을 뜻합니다. 날짜가 바뀌었다고 해서
  내용이 꼭 바뀐 것은 아닙니다.

**자체 점검 결과**
- PC(1280px)와 모바일(768/414/375/360px) 화면에서 가로 스크롤 없이 보이는지 확인했습니다.
- 점검 중 320px 이하의 좁은 화면(구형 소형 기기 폭)에서 영수증 이미지 카드가 고정 너비
  때문에 화면 밖으로 살짝 밀려나 가로 스크롤이 생기는 문제를 발견해, 최대 너비를 화면
  폭에 맞게 줄어들도록(`max-width:100%`) 수정하고, 그리드 레이아웃이 자식 요소를 충분히
  줄이지 못하던 부분(`min-width:0`)도 함께 고쳐서 280px 폭까지 정상적으로 보이는 것을
  확인했습니다.
- 키보드(Tab)로 메뉴·링크를 순서대로 이동할 때 포커스 표시(파란 테두리)가 보이는지
  확인했습니다.
- 메뉴·이메일·GitHub 링크가 모두 정상 작동하는지, 예시 문구나 빈 링크가 남아있지 않은지
  확인했습니다.
- 작업 링크 기능을 올리기 전에 `sample.csv`로 로컬에서 먼저 만들어 보고, 카드 3개가
  제대로 들어가는지, 분류를 비운 행이 '기타'로 나오는지, 공개=`N` 행이 빠지는지 확인했습니다.
  열 이름을 바꾼 파일 / 공개=`Y`가 없는 파일 / 링크 형식이 틀린 파일 / CSV 대신 웹페이지가 온
  경우로도 실행해, 네 경우 모두 멈춘 이유를 출력하고(링크 형식 오류처럼 특정 행의 문제일 때는
  행 번호까지) 결과 파일을 만들지 않은 채 멈추는 것을 확인했습니다.
- 작업 링크 블록의 제목('작업 링크')과 안내 문구에는 `data-en`을 넣어 EN 전환이 되게 했고,
  시트에서 온 카드도 `제목_EN` / `내용_EN` / `분류_EN` 열을 채우면 EN 전환 시 함께 번역되도록
  했습니다. 영어 열을 비워 둔 행은 영어 화면에서도 한국어가 그대로 보이는 것을 확인했습니다.
  푸터 날짜는 한/영이 같으므로 번역 대상에서 분리해, 영어 화면에서도 날짜가 함께 갱신되게 했습니다.
- 카드 목록은 화면이 좁아지면 한 줄에 하나씩 쌓이도록 해 휴대전화 폭에서 가로 넘침이 없는지,
  링크가 새 탭으로 열리고(`rel="noopener"`) Tab 키로 옮겨 다닐 때 포커스 표시가 보이는지
  확인했습니다.

**동료 의견·수정 결과**
- 디자인이 단조롭다는 평을 들은 바 있어 한 차례 뷰어와 디자인을 심미적으로 수정했습니다. 가벼운 모션과 오프닝을 추가하였으며, 마우스 커서에 맞춰 파란색 그라디언트가 이동합니다.
- 단순히 타인을 위한 정보 전달만이 아닌, 홈페이지의 관리나 업데이트 등의 내부적 편의성에도 주목하면 좋겠다는 의견을 들어 수업 내에서 배운 내용(3주차/5주차)을 활용해 구글 시트를 활용해 간편히 프로젝트 리스트 업데이트가 가능하도록 GitHub Action 워크플로를 구현하였습니다. 

**사용한 자료·AI 도움**
- 폰트: Google Fonts의 Gothic A1, IBM Plex Mono
- AI 도움: Claude Code(Anthropic)를 사용해 모바일 좁은 화면에서 가로 스크롤이 생기는
  버그(영수증 카드 고정 너비, 그리드 최소 너비 이슈)를 찾아 수정했고, 이 README의
  구조를 정리하는 데 도움을 받았습니다. 실제 화면 확인과 최종 점검, README의 최종 작성은 직접 진행하였습니다.
- 시트를 읽어 HTML을 만드는 `main.py`, 배포 워크플로 `.github/workflows/site.yml`,
  `index.html`에 넣은 주석 표시(`WORKS` / `UPDATED`)와 작업 링크 카드의 CSS를 함께 작성했습니다.
  특히 이 사이트의 EN 전환이 '페이지를 열 때 한국어 내용을 복사해 두고 영어와 맞바꾸는' 방식이고,
  푸터의 영어 문구에 날짜까지 한 문장으로 묶여 있어 날짜만 바꿀 수 없다는 점을 찾아, 날짜를 별도
  조각으로 떼어내 그 자리만 빌드할 때 채우는 구조로 잡았습니다. 작업 링크 카드도 시트의 영어 열로
  번역되도록 했습니다. 마지막으로 README의 사실 정보 기재 오류 혹은 오타 정정에 도움을 받았습니다
  어떤 시트 내용을 올릴지, 로컬 실행과 오류 상황 확인, 그리고 Pages 설정 변경 등은 직접 했습니다.
