# Soom260.github.io — 최수미 개인 홈페이지

## 1. 목적

경영학(한국외국어대학교, 경영학전공)을 공부하며 관심을 두고 있는 **서비스기획**과
**사회분석**을 한 페이지에 소개하기 위한 개인 포트폴리오 홈페이지입니다.
자기소개, 관심 분야, 진행 중인 프로젝트(kreceipt)의 문제의식·접근·현재 상태,
그리고 연락처(이메일·GitHub)를 한 번에 확인할 수 있도록 만들었습니다.
'기술개발연구프로젝트' 수업 과제(개인 홈페이지)의 결과물이며, 이후에도 계속 업데이트할 예정입니다.

## 3. 실행·수정 방법

이 저장소는 순수 HTML/CSS/JS 한 파일(`index.html`)로만 되어 있어 별도의 빌드 과정이 없습니다.

> 덧붙임(2026.10) — 화면·스타일을 고치는 방법은 위 설명 그대로입니다. 다만 아래 두 곳만은
> 배포할 때 GitHub Actions가 채워 넣습니다: **03 프로젝트 섹션의 '작업 링크' 카드**(구글 시트에서 읽어 옴)와
> **푸터의 마지막 업데이트 날짜**(빌드하는 날의 한국 시간). 자세한 방법은 아래 '작업 링크(구글 시트)로 관리하기'에 있습니다.

**로컬에서 확인하기**
```bash
git clone https://github.com/Soom260/Soom260.github.io.git
cd Soom260.github.io
# index.html을 브라우저로 바로 열어도 되고,
# 로컬 서버로 띄워서 확인해도 됩니다.
npx serve .
```

**내용 수정하기**
- 모든 텍스트·스타일·스크립트가 `index.html` 한 파일 안에 있습니다.
- 한국어 문구는 각 태그의 실제 텍스트로, 영어 문구는 `data-en` 속성에 들어 있습니다.
  우측 상단의 `EN`/`KO` 버튼을 누르면 두 언어가 전환됩니다. 문구를 바꿀 때는
  텍스트와 `data-en` 속성을 함께 수정해야 언어 전환이 깨지지 않습니다.
- 수정 후에는 아래처럼 커밋하고 `main` 브랜치에 push하면, GitHub Pages가 저장소 이름
  (`Soom260.github.io`)을 그대로 인식해 자동으로 https://soom260.github.io/ 에 반영합니다.
```bash
git add index.html
git commit -m "설명"
git push origin main
```

**작업 링크(구글 시트)로 관리하기**

'작업 링크' 카드는 `index.html`을 고치지 않고 **구글 시트에 적어서** 관리합니다.
시트를 웹에 게시해 만든 CSV 주소를 저장소 변수 `SHEET_CSV_URL`에 넣어 두고,
배포할 때 `main.py`가 그 주소를 읽어 카드를 만들어 넣습니다.
(주소는 코드나 화면에 넣지 않고 저장소 변수에만 둡니다.)

시트의 열 이름은 아래와 똑같이 맞춰야 합니다.

| 열 이름 | 규칙 |
|---|---|
| 제목 | 필수 |
| 내용 | 필수 |
| 분류 | 비워 두면 '기타'로 들어감 |
| 링크 | `http://` 또는 `https://`로 시작 |
| 공개 | 필수. `Y`인 행만 화면에 나옴(`N`은 숨김) |
| 제목_EN | 선택. `EN` 화면에서 보여 줄 제목 |
| 내용_EN | 선택. `EN` 화면에서 보여 줄 내용 |
| 분류_EN | 선택. `EN` 화면에서 보여 줄 분류 |

뒤의 영어 열 세 개는 **없어도 됩니다.** 열을 아예 만들지 않거나 칸을 비워 두면
그 자리는 `EN` 화면에서도 한국어가 그대로 보입니다. 채워 넣으면 상단 `EN` 버튼을 눌렀을 때
영어로 바뀝니다. 한 칸만 채워도 되고(예: 제목만 영어), 행마다 달라도 됩니다.

영어를 일일이 쓰기 번거로우면 시트 함수로 초벌 번역을 만들 수 있습니다. `F2` 칸에
아래처럼 적고 아래로 끌어 복사한 다음, 어색한 문장만 손으로 고치면 됩니다.

```
=IF(A2="","",GOOGLETRANSLATE(A2,"ko","en"))
```

**시트 수정이 사이트에 반영되는 시점은 두 가지입니다.**
- **매일 한국 시간 00:30 무렵** 워크플로가 저절로 돌아갑니다. 그래서 오늘 시트를 고치면
  별다른 조작 없이 **다음날 사이트부터 반영**됩니다. (`.github/workflows/site.yml`의 `schedule`)
- **바로 반영하고 싶으면** Actions 탭 → `Build and deploy site` → `Run workflow` 버튼을 누릅니다.

GitHub Actions의 예약 실행은 정확한 시각을 보장하지 않고 몇 분~수십 분 밀릴 수 있습니다.
또한 **공개 저장소에 60일간 커밋이 없으면 GitHub이 예약 실행을 자동으로 멈춥니다**(안내 메일이 옵니다).
그때는 Actions 탭에서 다시 켜거나 커밋을 하나 하면 됩니다.

열 이름이 다르거나, 공개=`Y` 행이 없거나, 링크 형식이 틀리면 **배포가 멈추고**
Actions 로그에 이유와 몇 번째 행이 문제인지 나옵니다. 이때는 배포가 일어나지 않으므로
직전에 성공한 화면이 그대로 유지됩니다.

형식을 확인하고 싶으면 저장소의 `sample.csv`로 로컬에서 먼저 만들어 볼 수 있습니다.

```bash
python main.py --csv sample.csv --output _site/index.html
# _site/index.html 을 브라우저로 열어 확인
```

## 4. 현재 상태

**완성도**
- 자기소개·관심 분야(경영·서비스기획, 사회분석)·프로젝트 소개·연락처(이메일, GitHub) 섹션을
  모두 채워 넣었고, 상단 메뉴로 각 섹션 이동이 가능합니다.
- 소개하는 프로젝트 **kreceipt**는 아직 출시 전 컨셉 단계이므로, 화면에 "컨셉·아이디어
  단계 — 사용자 시나리오와 핵심 화면 정리 중"이라고 진행 상태를 명확히 표시해
  완성된 것처럼 보이지 않도록 했습니다.
- 페이지 안에 전화번호·주소 등 불필요한 개인정보는 넣지 않았고, 연락처는 이메일만
  공개했습니다.
- 페이지의 유일한 그래픽 요소인 영수증 카드에 `role="img"`와 대체텍스트(alt)를 넣어
  화면에 보이는 내용을 글로도 확인할 수 있게 했습니다.
- 한/영 전환(EN/KO) 버튼 옆에 **음성 안내(🔊)** 토글을 추가했습니다. 켜면 각 섹션이
  스크롤로 화면에 들어올 때 그 섹션의 대체텍스트를 Web Speech API로 읽어주며, 언어
  전환 상태에 맞춰 한국어/영어 음성으로 전환됩니다.
- **작업 링크를 구글 시트로 관리하도록 바꿨습니다(2026.10).** 03 프로젝트 섹션의 kreceipt 설명
  아래에 '작업 링크' 카드 블록을 두었고, 그 내용은 `index.html`을 고치지 않고 구글 시트에 적어서
  관리합니다. 시트 열은 **제목 / 내용 / 분류 / 링크 / 공개** 다섯 개이며, 제목·내용·공개는 필수,
  분류를 비우면 '기타'로 들어가고, 링크는 `http://` 또는 `https://`로 시작해야 하며,
  **공개 열이 `Y`인 행만** 화면에 나옵니다.
- **매일 한국 시간 00:30 무렵 워크플로가 저절로 돌아갑니다.** 시트를 고쳐 두면 다음날 사이트부터
  반영되고, 바로 반영하고 싶을 때만 Actions 탭에서 `Run workflow`를 누릅니다. push할 때도 돌아갑니다.
- 시트 내용이 잘못된 경우(열 이름이 다름, 공개=`Y` 행이 없음, 링크 형식 오류, 게시된 CSV 주소가
  아닌 경우)에는 **일부러 배포를 멈추도록** 만들었습니다. 깨진 화면이 올라가는 대신 직전에 성공한
  화면이 유지되고, Actions 로그에 이유와 문제가 있는 행 번호가 남습니다.
- 푸터의 '마지막 업데이트' 날짜를 손으로 고치지 않고, **빌드하는 날의 한국 시간 날짜**가
  자동으로 들어가게 했습니다(예: `2026.10.04`). 매일 빌드가 돌므로 이 날짜는 '이 화면이 마지막으로
  만들어진 날'을 뜻합니다. 날짜가 바뀌었다고 해서 내용이 꼭 바뀐 것은 아닙니다.
- 시트에서 가져온 글자는 화면에 넣기 전에 모두 이스케이프하므로, 시트에 `<b>` 같은 태그를 적어도
  글자 그대로 보일 뿐 화면 구조가 깨지지 않습니다. 영어 칸은 이 사이트의 언어 전환이 `innerHTML`로
  글자를 넣는 구조라, 한 번 더 이스케이프해서 영어 화면에서도 태그로 해석되지 않게 했습니다.
- **시트의 `제목_EN` / `내용_EN` / `분류_EN` 열을 채우면 카드도 `EN` 버튼에 따라 번역됩니다(2026.10).**
  비워 두거나 열을 만들지 않으면 그 자리는 영어 화면에서도 한국어가 그대로 보입니다.
- 배포 방식이 '브랜치에서 바로 배포'에서 **GitHub Actions 배포**(`.github/workflows/site.yml`)로
  바뀌었습니다. 사이트에 필요 없는 파일(`main.py`, `README.md`, `sample.csv` 등)은 올라가지 않습니다.

**자체 점검 결과**
- PC(1280px)와 모바일(768/414/375/360px) 화면에서 가로 스크롤 없이 보이는지 확인했습니다.
- 점검 중 320px 이하의 좁은 화면(구형 소형 기기 폭)에서 영수증 이미지 카드가 고정 너비
  때문에 화면 밖으로 살짝 밀려나 가로 스크롤이 생기는 문제를 발견해, 최대 너비를 화면
  폭에 맞게 줄어들도록(`max-width:100%`) 수정하고, 그리드 레이아웃이 자식 요소를 충분히
  줄이지 못하던 부분(`min-width:0`)도 함께 고쳐서 280px 폭까지 정상적으로 보이는 것을
  확인했습니다.
- 키보드(Tab)로 메뉴·링크를 순서대로 이동할 때 포커스 표시(파란 테두리)가 보이는지
  확인했습니다.
- 메뉴·이메일·GitHub 링크가 모두 정상 작동하는지, 예시 문구나 빈 링크가 남아있지 않은지
  확인했습니다.
- 다크 모드(시스템 설정 연동) 및 한/영 전환이 정상 작동하는지 확인했습니다.
- 작업 링크 기능을 올리기 전에 `sample.csv`로 로컬에서 먼저 만들어 보고, 카드 3개가
  제대로 들어가는지, 분류를 비운 행이 '기타'로 나오는지, 공개=`N` 행이 빠지는지 확인했습니다.
  열 이름을 바꾼 파일 / 공개=`Y`가 없는 파일 / 링크 형식이 틀린 파일 / CSV 대신 웹페이지가 온
  경우로도 실행해, 네 경우 모두 이유와 행 번호를 출력하고 결과 파일을 만들지 않은 채
  멈추는 것을 확인했습니다.
- 작업 링크 카드의 제목과 안내 문구에는 `data-en`을 넣어 EN 전환이 되게 하고, 시트에서 온 카드
  내용은 번역 대상에서 빼 두었습니다(언어 전환 시 내용이 사라지지 않는지 확인). 푸터 날짜는
  한/영이 같으므로 번역 대상에서 분리해, 영어 화면에서도 날짜가 함께 갱신되게 했습니다.
- 카드 목록은 화면이 좁아지면 한 줄에 하나씩 쌓이도록 해 휴대전화 폭에서 가로 넘침이 없는지,
  링크가 새 탭으로 열리고(`rel="noopener"`) Tab 키로 옮겨 다닐 때 포커스 표시가 보이는지
  확인했습니다.
